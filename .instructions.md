## 2. Test-Driven Development (TDD) Mandate

To maintain extreme reliability, security, and catch edge cases early, this repository mandates a strict **TDD flow**:

1.  **Write Tests First**: For any new component or script, write the test spec file in `tests/` *before* creating or implementing the logic in `src/`.
2.  **Verify Red State**: Execute the tests using Vitest (`npx vitest tests/<your_spec>.test.js`) and confirm that the tests fail as expected.
3.  **Implement Logic**: Write code in `src/` to satisfy the tests. Iterate until the tests pass (Green state).
4.  **100% Code Coverage**: Run test coverage analysis (`npm run coverage` or `npx vitest run --coverage`). Maintain **100% test coverage** for all branches, functions, lines, and statements across your implementation. Do not submit or push code if it fails to hit this metric.
5.  **Mocks**: Emulate Chrome Extension Manifest V3 APIs in tests by importing and using the modular simulator provided in `tests/mocks/chrome.mock.js`.

## 3. Core Architectural Standards

*   **Manifest Specification**: Always use Manifest V3. No legacy Manifest V2 patterns.
*   **Frugal Permissions**: Maintain a zero-host-permission philosophy. We only require `"declarativeNetRequest"` and `"storage"`. Never request `<all_urls>` or specific host permissions; handle redirections dynamically utilizing `chrome.declarativeNetRequest` and internal extension routes.
*   **Dynamic Rules Engine**: Implement rule modifications programmatically using `chrome.declarativeNetRequest.updateDynamicRules` rather than static rule sheets. Map regex filters directly to dynamic rule identifiers.
*   **Regex Compatibility**: Validate user regexes using Chrome's native API: `chrome.declarativeNetRequest.isRegexSupported()` to ensure compatibility with Chrome's native RE2 engine before saving rules.

## 4. UI/UX and Aesthetic Guidelines

*   **Premium Visuals**: Build modern, high-contrast, glowing glassmorphic elements. Standard dark mode should utilize our curated HSL color palette:
    *   Base Slate: `hsl(224, 25%, 12%)`
    *   Glow/Warning Red: `hsl(354, 85%, 56%)`
    *   Green Success: `hsl(142, 70%, 45%)`
*   **Animations**: Integrate micro-animations and smooth CSS transitions (`transform`, `opacity`, `backdrop-filter`) for custom buttons, popup items, and UI state switches.
*   **Typography**: Import and use Google Fonts like `Outfit` or `Inter` to avoid generic system fonts.
